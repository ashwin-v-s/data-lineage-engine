Supported in this slice
Small, verifiable increments.

        
dbt manifest
Assets, descriptions, column names, tags, and declared dependencies are upserted.

        
OpenLineage events
Run identity, job identity, status, event time and input/output dataset metadata are stored.
Auto-detected JSON records
Import arbitrary JSON records without prebuilding Kairos assets. Source fields are preserved as metadata; unknown types remain generic assets, and relationships are not guessed.
Generic metadata graph
Store typed assets and explicitly supplied relationships for files, scripts, APIs, workflow tasks, model artifacts and other non-SQL resources. Attached evidence is kept distinct from unverified claims.
File inventory JSON
Register relative file paths, extensions, sizes, hashes, modification times, and parent-directory membership. This is inventory metadata, not proof that one file produced another.

        
PostgreSQL-backed catalog read
Counts and persisted assets are read back from the database after import.

      

      
Implementation boundaries & limits
Known gaps and constraints, not implied connections.

        
Direct source connectors
Universal JSON/file import is supported in this demo slice. Authenticated live connectors and scheduled scans for arbitrary systems are not yet implemented; each live integration still needs an adapter and access configuration.

        
SQLGlot service
The hosted SQL screen still uses a lightweight reference matcher.

        
Column-level lineage
The dashboard reads explicit persisted column mappings when available. Missing mappings remain unknown; the UI does not infer column lineage from column names alone.

        
Data-mode separation
The overview and lineage graph use sample records in Demo mode and catalog API records in PostgreSQL mode. An empty persisted catalog is not filled with demo data.
